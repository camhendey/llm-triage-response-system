# Version 1.1 refinement

**Sole developer: Cameron Hendey. Original workflow developed at JOEY in 2024; refined in 2025.** This revision packages the later software implementation; machine-generated run dates remain unchanged.

## Problem → decision → evidence

| Problem in the earlier software | Implemented decision | Verification |
|---|---|---|
| Selected D1 arrangement could produce a lounge draft | Ground offers in the active selected proposal; changing selection invalidates earlier drafts | `test_refinements.py`, selected-plan and draft-edit tests |
| Draft claimed a referral happened before a referral action | Separate internal review flag from explicit operator-reported external referral | Referral regression test |
| An allergy disclaimer elsewhere could hide a guarantee | Validate prohibited claims with local clause negation | Mixed safe/unsafe claim regression test |
| Party details and draft approvals could disagree | Invalidate on all fact changes; stale/policy checks at review | Allergy-change and selected-plan tests |
| Changed spend amount retained old agreement | Clear agreement when operator changes the amount | Minimum-spend test |
| Operator had to navigate many tabs and generic field controls | One conversation/arrangement/reply workspace, typed form and direct suggested-plan selection | UI interaction tests; Chromium captures |
| Outgoing offers were absent from future interpretation | Store exact reviewed replies as reported outbound messages; include them in context | Conversation and provider-context tests |
| Short acceptance had no grounded referent | Bounded offline resolution against the most recent offer; require human review | Contextual acceptance regression test |
| Optional occasion blocked otherwise complete bookings | Remove occasion from required confirmation fields | Policy test; frozen-case regression |
| Booking data ended at a draft | Add configuration-derived seating view and daily service handoff | Handoff cancellation/filter/formula tests; real screenshots |
| Shared UI connection complicated multi-tab behavior | One SQLite connection per browser session; stale version checks | Two-connection stale-edit test |

## Portfolio value

The case study can demonstrate translating a real operational workflow into an explicit domain model; separating language interpretation from authoritative decisions; transactional changes and audit history; tested exception handling; and an interface that links an inquiry to a service handoff. The refinements include traceable defect reproductions and a visible rationale, rather than an unmeasured claim that AI improved everything.

## Deliberate limits

The schematic is derived from synthetic table configuration, not surveyed restaurant geometry. Seating ranking is a fixed heuristic, not whole-evening optimization. The offline parser has narrow phrase coverage. The model can write only bounded greeting/closing prose; it does not freely generate booking facts. Outbound and referral records are human assertions, not verified integrations. Unsaved editor buffers last only for the browser session. Real model and operator-study results remain pending.
