# Manual workflow → software

Source: the owner-supplied original Reservation Coordinator introduction. The original PDF contains credentials and is deliberately excluded. Historical instructions provide context, not current policy.

| Need | Implementation | Boundary |
|---|---|---|
| Paper/email order and urgency | Original receipt, source, owners, task/hold priority, searchable queue | No automatic inbox ingestion |
| Fresh context each shift | Reviewed imports, durable shift, reload continuity, manual-only exception | Snapshots, not live availability |
| Check restaurant flow | Actual tables/groupings, conditional conflict assistance, recorded external check | Staffing and preferences remain manual |
| Book externally first | Reference, checklist, status, timestamp, evidence | No OpenTable writes |
| Call and handle no answer | Call outcomes, follow-up tasks, calling-window warning | Actual callback scheduling remains an owned task |
| Confirm visit requirements | Unknown/awaiting/historical/confirmed states with evidence | Historical notes are never auto-confirmed |
| Explain seating and show photo | Arrangement text, approved photo/caption or exception, attachment attestation | Real photos must be supplied |
| Acceptance before final confirmation | Exact source quote, operator attestation, plan hash | Human determines semantic acceptance |
| Distinct spend and manager policies | Separate thresholds, explicit amount/basis/inclusions, waiver and approval | Historical values not installed automatically |
| Feasibility before escalation/referral | Current external check before approval; current feasibility record before referral | Human records evidence |
| Table/time first and booking notes | Copyable package with requirements, acceptance, promises, Made by | External classification checked manually |
| Awaiting response is not complete | Offer task, independent acceptance/booking/response gates | No fabricated send receipts |
| Guest changes | Prior external allocation preserved; relevant evidence invalidated | Requested change never silently executes |
| Holds | Deadline and manual-release action on expiry | No automatic external release |
| Other outcomes | Reasons, recipient/handoff, matched outcome response | Active bookings require release first |
| Service readiness | Date-specific brief, CSV, reviewer receipt, changed-since-review flag | No automatic staff notification |
| Defensible portfolio | Synthetic regression tests, browser captures, timer export, study protocol | Human study and production impact unmeasured |

The project demonstrates decision support and accountability, not an autonomous reservation bot. Current restaurant inputs and observed human outcomes must come from evidence, not generated fixtures presented as real results.
